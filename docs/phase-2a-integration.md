## 下一阶段阅读体验

| 阅读任务 | 证据和发布条件 |
| --- | --- |
| 公司如何经营 | 从年报业务章节提取可以逐句核验的产品、客户、销售方式和收入确认逻辑。来源必须明确属于发行人或确定的业务分部。披露缺失的句子留空。 |
| 钱从哪里来 | 分开保存产品、营运分部、渠道和地区。每个维度独立核对分部表、币种、单位、合并范围、会计政策、总额及抵销。分母一致、税费处理一致、分部抵销可对账后才展示占比。无法重现合计时保留各自口径及原文。 |
| 经营发生了什么变化 | 同期间、同会计口径、同报告币种及同分部边界后才计算比较。并列呈现报告中的事实、产品计算和明确归属于管理层的解释。管理层未给出处时不推断数字变化的原因。发生重列时保留版本及标记。 |
| 官方公告告诉了我们什么 | 在明确授权后抽取正文中的主体、事项、披露日、发生日、状态、条件、金额及来源段落。区分提出、获批、生效、修订和撤回，相关附件须独立核验。目录仍会显示其覆盖范围和观察时间。 |

每条陈述记录发行人、源站、许可状态、文件版本、发布日期、适用期间、原文 URL 以及 HTML 段落锚点或 PDF 页、表、行。金额另存列标题、原始文本和单位换算。文本系统优先使用可复现的规则和确定性中文模板。保留已审阅的短句、状态或计算，遇到缺失、冲突或归因不明退回原文。建议沿用本地和按需缓存，控制单次解析大小与耗时，暂不引入付费模型。媒体作为单独来源类型评估授权，并始终保留归属及出处。

首轮用已获准的零售、消费品、银行三种经营模式建立独立人工核验集。每个模式至少核对一段业务说明、一个可复核的收入维度及两项经营变化；选取已核验正文的真实公告测试修订和状态变化。财年错位、累计混用、税费和归母范围、缺失分部抵销、审批未生效、管理层前瞻说法以及只见目录未见正文应为拒绝或降级用例。通过的样本句应全部可回到原文并重现计算。界面先显示经营结论和原文出处，用户仍可打开报表查看上下文。
